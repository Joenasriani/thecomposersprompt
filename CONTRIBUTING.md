# Contributing

Contributions should improve musical accuracy, educational clarity or the usability of the workbook.

## Report a correction

Include the chapter or practice room, the current wording or behaviour, your proposed correction, and a source or reproducible example. Distinguish a musical fact from an interpretation or a platform-specific observation. For tool behaviour, record the product version and date, where known.

## Propose a change

Open a pull request with a focused change and a short explanation. Keep explanations before examples, retain readable typography and visible note markers, and preserve the ability to run the workbook as a self-contained HTML file. Do not introduce analytics, credentials or network dependencies without discussing the need first.

For musical changes, verify the note names, octave numbers, intervals, chord tones, bass notes and playback. Check all related selector options, not only the default example. For interface changes, check keyboard navigation, narrow screens, horizontal scrolling, prompt copying, stopping audio and browser-local progress. Report the browsers and checks actually used.

The manuscript is embedded in `index.html` as reading-section data. Keep each section's rendered HTML and searchable text consistent. Clearly distinguish revised teaching content from retained original wording; do not silently remove the correction history.

## Scope and licensing

Submit only material you have permission to contribute. Contributions to the existing interactive workbook are intended to be distributed under the repository's CC BY 4.0 license. This does not apply to the separately published, all-rights-reserved final PDF of *The Composer’s Prompt*. Do not submit or redistribute that PDF as though it were CC BY 4.0 licensed. Identify third-party material, attribution requirements and any exceptions explicitly. Do not include secrets or personal information in issues, examples or pull requests.
