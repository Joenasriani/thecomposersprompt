Chapter 31.5: Stable Audio, MusicGen, and AIVA

The book has focused on Suno and Udio because they are the most widely used general-purpose platforms, but the same theoretical concepts apply across the tool landscape. This chapter extends the specification discipline to the other major tools.

31.5.2 Stable Audio 3.0

Stable Audio's prompt model is producer-grade and instrumental-first. It is designed for audio-to-audio workflows, inpainting, and texture-focused generation. Its prompt formula follows the general architecture: Genre + Instruments + Mood + BPM, with additional tags like TrackType: Instrument to signal that the output should be instrumental rather than vocal.

The distinctive parameter is noise level, which ranges from 0.3 to 0.9 and controls the variance of the output relative to the reference audio. A noise level of 0.3 produces a close variation; a noise level of 0.9 produces a distant one. The Hijaz exercise in Chapter 32's capstone uses noise level 0.5 as the midpoint between fidelity and exploration.

Prompt example:

"Ambient, solo cello, slow evolving textures, sparse pizzicato, 66 BPM, TrackType: Instrument, warm analog, noise level 0.5"

31.5.3 MusicGen / AudioCraft

MusicGen is open-source and trained on 20,000 hours of licensed music. Its prompt model is text plus optional audio conditioning, and its distinctive feature is melody conditioning—the model can be given a melody line (as audio or MIDI) and asked to generate an accompaniment or variation.

For the composer, melody conditioning is a specification tool: instead of describing the melodic contour in words, the composer provides the contour as audio, and the model uses it as a constraint. This is especially useful for motivic development and theme-and-variation work, where the melodic identity is the specification.

Workflow example:

  1. Compose a 4-bar melody in a DAW.
  2. Export the melody as a WAV file.
  3. Pass the melody as audio conditioning to MusicGen with a text prompt: "string quartet accompaniment, D major, 90 BPM, warm".
  4. MusicGen generates a harmonic accompaniment that follows the melody.

31.5.4 AIVA

AIVA's prompt model is composition-workflow oriented. It uses Roman numerals rather than chord letters because its parser generates faster and more accurately from numerals: I, V, vi, IV produces a better result than C - G - Am - F. AIVA is mode-aware but not for non-functional traditions—it is built on Western functional harmony and does not handle maqam or raga systems well.

Prompt example:

Bb major, I-vi-ii-V, 140 BPM, jazz, swing feel, piano trio

The Roman numeral rule is tool-specific, not universal. Suno and Udio both handle chord letters well when they are bracketed; AIVA prefers numerals. The theory is the same; the encoding differs.
